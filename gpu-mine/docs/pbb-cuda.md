# PBB 长跑测号与性能

PBB CUDA 在 GPU 上运行完整评分。PBB WGSL 在 Vulkan 上生成候选、运行整数 Q 门、完成技能洗牌和保守 G3，只将剩余候选交给原版 PBB 标量 CPU 做完整评分与收集。两条路线共用队伍、Base16384 编号、计划、CSV 和停止逻辑。

## 日常使用

CUDA 版需要 CUDA Toolkit 12.8、MSVC x64、Python 3。WGSL 版需要可用的 Vulkan 计算驱动、Rust 和 C++17 工具链，支持 Windows x86_64 和 Linux x86_64。两条路线从同一份 PBB 头编译。默认查找仓库旁边的 `PBB/source/pbb/native/src`。自定义位置用 CUDA 的 `-PbbSource` 参数或 WGSL 的 `PBB_SOURCE_DIR` 环境变量。

在仓库根目录构建并用已知有命中的有限区间验收。

~~~powershell
& ./gpu-mine/benchmarks/pbb-cuda/build.ps1 -OutputDir target/pbb-cuda
cargo build -p pbb-wgsl --features native-pbb --release --locked
$plan = './gpu-mine/benchmarks/pbb-cuda/fixtures/football-real.kv'
./target/pbb-cuda/pbb-cuda.exe --mine --out target/pbb-cuda-demo --plan $plan --start 15118306 --count 65537
./target/release/pbb-wgsl.exe --mine --out target/pbb-wgsl-demo --plan $plan --start 15118306 --count 65537
~~~

每次用 `--out` 指定新目录，产物为 `results.csv`。区间是 `[start,end)`，可用 `--count` 或 `--end` 指定结束位置。省略两者后可以持续跑，按 Ctrl+C 会写完当前批次、刷新 CSV 并报告 `next_id`。续跑时用该值作为 `--start`，沿用评分计划、队伍、模板和新的输出目录。

可用 `--team` 和 `--name-template` 覆盖文件或默认输入。模板含一个 `[]`，生成后最多 252 个 UTF-8 字节。复制足球计划可编辑 `min_*`、`ptt_*`、`score_list`、`score_mode`、`collect_mode` 和自定义收集阈值。主命中与蓝号共用一份 CSV，由 `keep` 和 `blue` 两列区分。带引号的名字按 CSV 规则转义。

## 实测

### CUDA 与 WGSL 同轮复测：+10.6% / +6.4%

RTX 5060 Ti 16 GB、Ryzen 7 5800X，同一[完整足球计划](../benchmarks/pbb-cuda/fixtures/football-real.kv)，从 ID 0 开始，Q 工作组 128、每批 16,777,216，WGSL 尾部用 6 个 CPU 线程。新、旧 CUDA 和 WGSL 各跑两轮，每轮实跑 60.00–60.04 秒。各轮串行，第二轮反转各路线的新旧顺序；端到端计入回读、评分和 CSV。

| 路线 | 两轮 T/天 | 候选/秒（中位数） | T/天 | T/周 | 同轮增幅 |
| --- | ---: | ---: | ---: | ---: | ---: |
| CUDA 旧版 | 60.36 / 58.80 | 689,531,263 | 59.58 | 417.03 | — |
| **CUDA 新版** | 67.36 / 64.46 | **762,869,851** | **65.91** | **461.38** | **+10.6%** |
| WGSL 旧版 | 35.71 / 35.68 | 413,154,454 | 35.70 | 249.88 | — |
| **WGSL 新版** | 38.03 / 37.96 | **439,769,881** | **38.00** | **265.97** | **+6.4%** |

新版 WGSL 为同轮新版 CUDA 吞吐的 **57.6%**。本轮旧 CUDA 和旧 WGSL 的绝对吞吐均低于历史中位数，增幅只用上表的同轮新旧对照。T = 10¹²，日、周值为一分钟端到端吞吐的折算。

- **CUDA**：精简固定布局的共享地址和游标计算；Q 前核以四字节转换并稳定压缩原版属性。G3 中核在共享内存原位重建完整排列，裁剪路径核间只传 ID，在 16,777,216 个/批时少分配 512 MiB 快照。通用模板、G3 精算和尾评分语义不变。
- **WGSL**：固定布局的双步换位改用有序覆写处理同址别名；裁剪区四步拆成两对读写。Q 属性扫描四字节展开，以同一个整数谓词保留原顺序。GPU G3 仍只做保守筛除，最终由原版 CPU 精算。两轮 Q 约 **56.0 秒**，G3 约 **2.5 秒**；继续提速优先优化前核。
- **结果一致**：四份新版输出的公共 ID 区间内 **130 条命中逐行一致**；纳入两条路线的旧版后，八轮公共区间内 **125 条**逐行一致。CUDA 新旧四轮的公共区间内另有 **210 条**逐行一致。

旧版可在提交 `8ad8b30` 的独立工作树按同样参数构建。见下方[对拍和一分钟基准](#对拍和一分钟基准)。

### WGSL 双门控：39.19 T/天（上轮历史数据）

按同一[足球计划](../benchmarks/pbb-cuda/fixtures/football-real.kv)，从 ID 0 开始。前核工作组 128，中核 64，尾评分为六线程 CPU；新版每批 16,777,216 个候选。端到端计入 Vulkan 提交、回读、原版评分和 CSV。

| 版本 | 实际秒数 | 完成候选 | 候选/秒 | T/天 | T/周 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 旧 WGSL 同机复测，524,288 个/批 | 60.001244 | 3,973,578,752 | 66,224,939 | 5.72 | 40.05 |
| 新 WGSL 第 1 轮 | 60.029284 | 27,296,530,432 | 454,720,242 | 39.29 | 275.01 |
| **新 WGSL 第 2 轮（中位数）** | **60.024581** | **27,229,421,568** | **453,637,845** | **39.19** | **274.36** |
| 新 WGSL 第 3 轮 | 60.041882 | 27,212,644,352 | 453,227,703 | 39.16 | 274.11 |

新版为旧版的 **6.85 倍**，达到已验收 CUDA 三轮中位数的 **60.4%**。中位数轮过 Q 约 3.47 亿个，原版复核过 G3 约 199 万个；正常批次只回读第二道门控保留的 ID。该轮 GPU 两段时间戳累计 **59.03 秒**，其中 Q 约 **57.04 秒**、G3 约 **1.99 秒**；CPU 原版精算大部分与下一批 GPU 重叠。不能把 GPU 时间戳之外的约一秒当成全部 CPU 用时。同次 CUDA 复测达 **753,803,204 候选/秒（65.13 T/天）**，三轮与 CUDA 的公共范围内各有 **137 条命中逐行一致**，也各与旧 WGSL 的公共范围内 **22 条命中逐行一致**。

实现要点：

- **GPU 前筛**：31 字节前缀且无后缀时特化 50 字节键环，合并双步共享访存，静态展开字面密钥。第二轮只保留 Q 观察的前 88 槽；凑不够 31 项就重新走完整排列。固定布局的 Q 前核省掉运行时边界检查；通用模板和 G3 保留检查。
- **GPU G3**：用完整排列计算原版技能，16.16 定点衰减向上取整，非负权重给出 G3 分数上界。G3 不使用暗影维，只有三个上界都低于保守阈值才丢弃；FREE 或任何不确定项都交给原版 CPU。从上游读取权重，构建时核对技能、衰减、暗影系数和两套 HP 排序的中间和。GPU 低精度不会写进结果，不需要 Vulkan FP64。衰减更新用 `ceil(Z × (12800 − f × c) / 12800)`，其中 `Z` 是缩放后的状态，`c` 为原比例的整数百分数；频次至多 106，所有中间量和点积均在 u32 范围内。比较阈值下移至少一个定点单位（1/65536），覆盖原版 binary64 的累积舍入误差。
- **宿主**：同一次提交跑 Q 和 G3，回读只取压缩尾队列；溢出可完整回读。二维派发支持大批次。正式测号按序写 CSV，取消时排空已提交批次再报告下一 ID。

### CUDA 共享技能中核：64.93 T/天（上轮历史数据）

同一[完整足球计划](../benchmarks/pbb-cuda/fixtures/football-real.kv)、同一 31 字节前缀、从 ID 0 开始。每批 16,777,216 个候选，前核工作组 128，中核工作组 64。每轮实跑至少 60 秒，计入回读及 CSV 输出。

| 轮次 | 实际秒数 | 完成候选 | 端到端候选/秒 | T/天 | T/周 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 60.018733 | 45,181,042,688 | 752,782,348 | 65.04 | 455.28 |
| **2（中位数）** | **60.012079** | **45,097,156,608** | **751,467,998** | **64.93** | **454.49** |
| 3 | 60.012925 | 45,080,379,392 | 751,177,838 | 64.90 | 454.31 |

相比显式共享访存版的 **50.15 T/天**再快 **29.5%**。三轮在共同候选区间的 **229 条命中逐行一致**；与早期三核复测在共同区间的 **148 条命中逐行一致**。

中核把完整 S-box 放在每个线程独占的共享内存列，避免在局部内存中做 PRGA 的随机访问。技能频率只依赖属性序列的最后 68 项，从后向前直接取 16 组四项最小值和 2 组两项最小值；两轮 40 槽洗牌、G3 判定、完整评分和 PTT 保持原版。快照满时仍重建完整排列，不丢候选。

RTX 4090 已成功构建 `sm_89`，未做真机测速。要达成 180 T/天，需比此卡约快 2.77 倍；单按 SM 数与频率外推约 200 T/天，但共享内存、批次和 SM 调度的缩放不保证线性。建议在 4090 上用下方一分钟命令实测。

### 前缀裁剪版：RTX 5060 Ti 16 GB（历史）

依然用[完整足球计划](../benchmarks/pbb-cuda/fixtures/football-real.kv)，从 ID 0 开始，128 线程、每批 16,777,216 个候选，包含完整评分与 CSV。前缀裁剪的三轮 60 秒为 **49.37、49.50、49.48 T/天**，中位数 **572,687,036 候选/秒、49.48 T/天、346.36 T/周**。二进制同卡的前一版复测为 **479,413,687 候选/秒、41.42 T/天**，公共区间 **148 条命中逐行一致**。

适用 31 字节字面前缀、无后缀的模板。首轮完整执行；第二轮仍计算所有游标，前 88 个槽保持与原版完整排列一致。处理第 88 个槽以后，交换读到的随机槽旧值只会进入刚处理完且不再观察的槽，因此可以略掉该读取和固定槽写回。前缀能收齐 31 项时，一级 Q 结果与完整排列一致；收不齐的候选保留到后核重建，绝不当作失败。过门候选也始终重建完整排列才执行 PRGA 和 G3。其它模板保留完整排列路径。

新前核用 32 位共享内存地址发出显式读取，先发两个随机字节读再处理别名，并预打包稳定的前缀快照与字面密钥。裁剪后已退出观察范围的随机槽写入可保留，避免逐 lane 预测；写入保留前缀与未来槽的顺序仍与原版相同。

显式共享访存版的三轮 60 秒分别为 **50.15、50.59、49.33 T/天**，中位为 **580,448,086 候选/秒、50.15 T/天、351.06 T/周**。中位数轮处理 34,829,500,416 个候选并输出 179 条普通命中；三轮各与前一版公共区间的 148 条命中逐行一致。

`--batch 16777216 --block 128` 为本机冲刺参数，默认批次不变。需约 5.4 GiB 设备缓冲，另外还要留出 CUDA 上下文和桌面显存。其它模板或设备应重新测量。RTX 4090 需要 `-Arch sm_89` 实机验证，不能据此宣称 180 T/天。

| --- | ---: | ---: | ---: | ---: | ---: |
| 第 1 轮 | 60.016366 | 28,462,546,944 | 474,246,425 | 40.97 | 286.82 |

### 三核版的实现与运行参数

- **前核**只计算原版 Q 门需要的属性，不先计算旧 V。31 字节前缀、无后缀时，两个相邻 S-box 槽一次读写；其他模板继续走通用交换。
- **中核**从有界快照恢复完整排列与旧 V，运行精确 G3。三张 G3 平面的暗影系数都是零，构建时检查这一前提。快照装满仍计算每一位候选，多出的候选重新生成主号排列。
- **尾核**为每个候选分配一个 warp。PTT 的基线、一项 HP、七项属性和十八项技能变体分给不同 lane。每个变体仍按原顺序累加，仅在 warp 内取最大值，最后按原版取整。
- `--batch 8388608 --block 128` 是本卡足球计划的冲刺配置。批容量越大占用显存越多；默认长跑仍为 1,048,576，显存不足时用较小批次。PTT 等后段语义不随批大小改变。

~~~powershell
# RTX 5060 Ti 16 GB：以完整足球计划持续测号
./target/pbb-cuda/pbb-cuda.exe --mine --out target/pbb-live --batch 16777216 --block 128
# RTX 4090：单独构建 Ada 版本，再在目标卡上测量
& ./gpu-mine/benchmarks/pbb-cuda/build.ps1 -Arch sm_89 -OutputDir target/pbb-cuda-ada
./target/pbb-cuda-ada/pbb-cuda.exe --out target/pbb-ada-minute --backend cuda --seconds 60 --batch 16777216 --block 128
~~~

### 两阶段早期实测（历史）

在 RTX 5060 Ti（驱动 621.24，CUDA 12.8 / `sm_120`）上，从 ID 0 开始跑同一 [足球计划](../benchmarks/pbb-cuda/fixtures/football-real.kv)：十族 all、五个 PTT 族、collect_mode=1，批次均为 1,048,576。前核 block 128；新后核按 8 × SM 数派发，这张卡为 288 个 block，每 block 64 线程。

| 同口径实测 | 实际秒数 | 完成候选 | E2E 候选/秒 | T/天 | T/周 |
|---|---:|---:|---:|---:|---:|
| 旧两阶段复测（16 × 32 后核） | 60.001805 | 2,991,587,328 | 49,858,289 | 4.31 | 30.15 |
| **新两阶段（三轮中位数）** | **60.005002** | **14,532,214,784** | **242,183,388** | **20.92** | **146.47** |

三轮分别为 **21.11、20.89、20.92 T/天**，中位数是同机旧版复测的 **4.86 倍**。三轮与旧版在共同 ID 区间的 16 条主命中逐行相同；三轮彼此在各自公共区间的 78 条命中也逐行相同。中位数轮共 78 条主命中、0 条蓝号、274,283 个候选产生非零潜力分。

提速来自三处：

- **稀疏模型点积**：普通分与 PTT 同样按原权重下标顺序，只跳过为零的特征及其交互项，不再物化每份 1,123 项的稠密数组。生成器检查原表一阶、二阶顺序并从原表生成交互下标（包含原有缺项）。QP/QD 仍逐项收回 float，其余仍 double，编译保留 `--fmad=false`。后核每线程编译栈帧由 21,648 B 降到 4,080 B。
- **后核铺满 GPU**：取代旧的 16 个 block，按 SM 数铺开，让各 SM 都能处理压缩候选；多批 block 分摊潜力路径的长尾。
- **前核双步 KSA**：在原有每 lane 独立的转置共享内存上做字节交换，相邻两步提前读取，用首步新值处理地址重叠，保留原写入顺序、V 和首道门控。

两阶段比单核快 **68.91%**，约为本次六线程标量 CPU 的 **12.80 倍**。轻量前核只做打包 S-box、原属性序列与同一首道 Q 门；**1.277%** 候选进入后核，后核依然跑完整的 Q/PRE/FREE、各族评分和 PTT。两阶段的 16 条正式主命中内，与单核 CUDA 公共区间的 8 条、与 CPU 公共区间的 1 条均逐行一致。两阶段另有 **56,543** 个候选产生非零潜力分。

## 旧版 WGSL 与 CUDA 的差距

只有一级门的旧 PBB WGSL 是 **GPU 一级 Q 门 + 六线程原版标量 CPU 评分**：每批回读过门 ID，CPU 重新生成名字和完整排列，再做后续门控、完整评分和 PTT。CUDA 的全部评分阶段在显卡上完成，还额外优化了两轮 KSA、精确 G3 压缩和 PTT 调度。对比体现的是整条执行路径的差别，不是 WGSL 和 CUDA 语言之间的固定倍数。作为参考，执行路径更相近的 XP/XD 两版为 **86.24 对 122.82 M 候选/秒（1.42 倍）**。

WGSL 的一分钟样本中，Q 计算通道的 GPU 时间戳累计约 **14.16 秒（23.6%）**，折合前核 **2.60 亿候选/秒**。其余约 **45.85 秒**混有批次提交、回读等待、解码排序、CPU 重算和输出，不能全归给 CPU。约 **1.276%** 候选过 Q，有效 ID 载荷仅约 **3.13 MB/s**；平均每批过门约 **6,690** 项，超过首段 **4,096** 个槽，经常需要二次提交和同步回读。没有证据表明 PCIe 带宽饱和。CUDA 的设备计时包含 Q、重建、G3 和尾评分，不能直接当作同一前核对照。

新版已把技能和 G3 放到 GPU，把正常流程缩成一次提交和一次尾列回读。CPU 评分与下一批重叠后，主要瓶颈转为显卡上的两轮 KSA。后续应先做相同工作组、批次、ID 范围及输出的 Q-only 对照；不能直接把 CUDA 的全部阶段计时当作 CUDA 前核耗时。

## 支持的评分语义

- 十个族：QP、QD、PP、PD、CQD、CP、FP、WC、FS、PJ；按原 plan 族门顺序、模型权重、SP1/SP2 的 46 个特征与多项式索引。CUDA 和 WGSL 的最终评分都保留原版双精度语义；QP/QD 仍按原先逐项收回 f32，QP 仍按原规则扣分。
- 原 PBB 的状态生成、前置属性逻辑和技能，影子、守护、护盾、隐匿衍生维不变。PBB 与旧 XP/XD 的翻倍槽条件、HP 排序路径以及 sum 语义不同，不共用旧模型。
- all / any、评分族别名和精确潜力规则；任一已启用族普通达标时跳过所有 PTT。collect_mode 0 / 1 / 2，特殊收集独立于主输出但仍要求原评分门存活；mode 2 保留 sum−HP/3 的整数除法。
- 数据来源由 [生成器](../benchmarks/pbb-cuda/generate_pbb_device_scoring.py) 在构建时读取本机 PBB 的评分头；保留 11 张模型表（CQD 有两张）、19 张门控权重表。PBB 第三方头和生成后的模型数据不入库；构建目录保留原文件哈希。

### 继续降精度的收益上限

Q 本身是精确整数门，耗时主要来自两轮 KSA 的排列读写。WGSL 的 G3 已使用 16.16 定点保守上界；本轮一分钟中 G3 约 2.5 秒，即使无代价地消除这段也只提升约 4.4%。放松上界会增加回读与 CPU 精算；尾列超过 4,096 项还需额外回读。因此本轮保持 G3 精度和精算分工，优化 Q/KSA。

若高通过率计划将来实测卡在尾部，可先给各族门构造保守上界，把不确定项送回原版精算。普通分不达标并不排除 PTT 救回，蓝号也需独立判定；不能把只针对普通分的低精度结果当成最终淘汰条件。

## 对拍和一分钟基准

构建后的二进制可运行 `--validate` 捕获逐字段对拍，或用 `--seconds 60` 测端到端吞吐。测速产生的临时结果无需入库。

~~~powershell
$exe = './target/pbb-cuda/pbb-cuda.exe'
$wgsl = './target/release/pbb-wgsl.exe'
& ./gpu-mine/benchmarks/pbb-cuda/verify.ps1 -Binary $exe -OutputDir target/pbb-cuda/validation -Path split -Block 128
& ./gpu-mine/benchmarks/pbb-cuda/verify.ps1 -Binary $exe -OutputDir target/pbb-cuda/validation-direct -Path direct -Block 64
& ./gpu-mine/benchmarks/pbb-cuda/verify.ps1 -Binary $wgsl -OutputDir target/pbb-wgsl-validation -Path wgsl -Block 128
$plan = './gpu-mine/benchmarks/pbb-cuda/fixtures/football-real.kv'
& $exe --out target/pbb-cuda/validation-extended --plan $plan --validate 4194305 --block 128 --batch 1048576
& $exe --out target/pbb-cuda/football-60s --plan $plan --backend cuda --seconds 60 --block 128 --batch 16777216
& $wgsl --out target/pbb-wgsl-60s --plan $plan --backend wgsl --seconds 60 --block 128 --batch 16777216 --threads 6
~~~

可用 [football-real.kv](../benchmarks/pbb-cuda/fixtures/football-real.kv) 或其它计划覆盖评分阈值、潜力、任意/全量、收集条件和枚举输入；--plan 不传时使用足球评分参数。输入为带一个 [] 的 UTF-8 模板、单槽 Base16384；名字上限 252 字节以适配原 PBB 影子缓冲。--cuda-path direct 用完整单核作对照；split 依次处理 Q 门、G3 门和完整评分。固定布局的 G3 中核用 Q 队列的 ID 在共享内存中重建完整排列；通用模板沿用有界快照，快照满时重建。两条 CUDA 路径都使用同序稀疏点积，CPU 保留未修改的原版稠密评分。

### 验证覆盖

- 本轮 CUDA 与 WGSL 新版各通过 17 组、558,105 个候选的原版矩阵。CUDA 另在批容量 16,777,216 下对拍 1,048,577 个跨 u32 候选；WGSL 用 32 线程二维派发对拍 2,097,153 个跨 u32 候选。Clippy `-D warnings`、Linux 构建及 CPU 路线、CUDA `sm_89` 编译通过；RTX 4090 和 RX 580 均未实测。
- 共享技能中核通过 17 组、558,105 个候选的 CPU 原版对拍，以及 1,048,577 个跨 u32 的扩展候选。单核、强制快照只容纳 1 个候选的重建路径，以及重新构建的 WGSL 后端也分别通过完整矩阵。
- 前缀裁剪通过 17 组、558,105 个候选的原版 CPU 对拍，另在 16,777,216 的批容量下校验跨 u32 的 1,048,577 个候选。验证模式额外核对精确 Q 门通过计数；完整记录、评分、潜力和收集集合沿用原版口径。
- 三核和单核各对拍 17 组、558,105 个候选；另用仅容纳 1 个快照的独立构建强制触发回退，并复验全矩阵。三核在 8,388,608 的批容量下另对拍 1,048,577 个跨 u32 进位的候选，同时验证有实际命中的 `--mine`。Ada `sm_89` 构建通过，RTX 4090 尚未实测。
- 早期稀疏版真机对拍覆盖完整验证矩阵。单核和两阶段各 **16 组 / 549,910 个候选**，两阶段另在正式 block、batch 上额外对拍 **4,194,305 个候选**。每组既全捕获逐字段和计数，又按正式筛选验证主结果及特殊集合的并集。十族整数分、潜力、属性、技能、频次、门、集合均精确相等，双精度诊断量用明确误差界比较。覆盖 32 位进位、u64 末端、空前后缀、固定后缀和 252 字节名字上限。
- 双步 KSA 前端在 96,287 项 CPU 对拍上逐值匹配完整 S-box、31 个属性字节、V 和原一级门档位（含 10 种附加模板和 u32/u64 边界）。
- 原足球计划有真实普通命中；诊断计划有仅潜力救回的命中以及三个单样本覆盖五族 PTT。all 与 any 的命中集合一致，但后续未计算列为零。自定义收集覆盖主结果为空、两集合相交和整数除法的边界；正式足球窗口没有自然出现 mode 1 的特殊号，不用诊断阈值冒充生产成绩。对应的四个 mode 1 判据另用原版 CPU 流程的合成边界核对。
- WGSL 双门控通过 17 组、558,105 个候选的原版矩阵，逐 ID 比对拒绝/PRE/FREE 档位、Q 压缩集合及完整结果。另在 32 线程和二维派发下，对拍 2,097,153 个跨 u32 边界的候选。生产路径验证了 Ctrl+C 写完已提交批次、按 `next_id` 续跑，结果与整段一次测号逐行一致。已在 RTX 5060 Ti 验证，RX 580 的驱动状态见下节。

## RX 580（Polaris）

历史探测确认 Debian 13 识别 **RX 580 2048SP 8 GiB**，内核由 `amdgpu` 接管。已有 Vulkan 加载器，当时未找到 AMD ICD，`vkCreateInstance` 返回 `VK_ERROR_INCOMPATIBLE_DRIVER`，还未进入物理 GPU 枚举。普通用户对渲染节点的权限、RADV 的计算限制、PBB 正确性和吞吐均未实测。

在 Debian 13 上，AMD Vulkan ICD 由 `mesa-vulkan-drivers` 提供，`vulkan-tools` 提供诊断命令。让实际运行的普通用户取得 `/dev/dri/renderD*` 访问权限（`render` 组或等效 ACL），由同一用户确认 `vulkaninfo --summary` 能列出 RADV 实体 GPU。PBB WGSL 不需要 FP64、FP16、子组特性或 `/dev/kfd`。先用 32 线程工作组（8 KiB 工作组存储）；64/128 线程分别需 16/32 KiB，以 Vulkan 驱动报告为准。

~~~bash
vulkaninfo --summary
cargo build -p pbb-wgsl --features native-pbb --release --locked
./target/release/pbb-wgsl --backend wgsl --out target/pbb-rx580-check \
  --plan gpu-mine/benchmarks/pbb-cuda/fixtures/football-real.kv \
  --start 15118306 --validate 65537 --block 32 --batch 8192
~~~

小范围对拍通过后，再按同样的 `--seconds 60` 口径实测吞吐；目前没有 RX 580 实机性能数据。
