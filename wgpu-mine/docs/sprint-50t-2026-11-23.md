# RTX 5060 Ti：CUDA 与 WGSL 冲刺 50 T/周（2026-11-23）

50 T/周等于 82,671,958 候选/秒。本轮基准统一以完整端到端时间分母，包含 GPU 名字生成、KSA、属性/技能/影子、原版 XP/XD、命中回读、CPU 复核、CSV 写入和 flush，不含初始化或预热。不以候选数量作为正式终止条件：各后端按单调时钟跑 60 秒，停止新批之后收完已派发的一批。短测只用于筛选，不作为达标成绩。

## 最终分钟实测

两个后端均超过 82,671,958 名/秒。本表是各自最快的有效 60 秒样本，串行测量；输入与评分相同，分别选用实测较优的批次。

| 后端 | 批次 | 实际秒数 | 完成候选 | E2E 名/秒 | T/天 | T/周 |
|---|---:|---:|---:|---:|---:|---:|
| WGSL / Vulkan | 3,145,728 | 60.008346 | 5,039,456,256 | **83,979,257** | **7.26** | **50.79** |
| CUDA full32 | 2,097,120 | 60.023764 | 6,404,604,480 | **106,701,148** | **9.22** | **64.53** |

相比[上轮同条件的一分钟数据](../benchmarks/wgsl-cuda-60s-baseline.csv)，WGSL **+31.58%**，CUDA **+40.85%**。CUDA 在最终源码的独立重建中另跑到 **104,669,778 名/秒、63.30 T/周**。完整分钟记录见 [原始指标](../benchmarks/sprint-50t-runs.csv)。WGSL 过线幅度约 1.58%，换驱动或后台负载需要复测。

配置：同一 RTX 5060 Ti（驱动 621.24；CUDA Toolkit 12.8.93；WGSL 经 Vulkan），同一 Base16384 名字模板、同一队伍、从 ID 0 开始，p550/x4000/d5000，GPU 每组 32 候选。T = 10¹²，日周是持续满载的理论折算，不是已运行一周；高命中时仍可能受 CPU 和 CSV 吞吐限制。未改功耗、频率、阈值、模型或候选枚举。

## CUDA：分段 KSA、稳定字节扫描

1. [打包 S-box 交换与单槽 KSA](../benchmarks/cuda-mine.cu)：复用已经读取的两个共享字，原位异或差量更新，正确处理两个槽在同一字的情况。只有守卫确认模板中有一个连续的 Base16384 槽且其余全是字面字节，才分段直取 18 个生成字节；重复槽走通用回退；固定后缀与 256 B 边界均有对拍。
2. 完整扫描按原顺序一次读取四个槽；属性中间值、技能索引和频率缩为字节。影子只读取影响结果的前 31 项。技能洗牌状态、余数、技能 ID 分别小于 40，原加和不会触发 u8 截断，因此把两次取模合成一次。不改任何评分模型。
3. 逐级对拍后再叠加：原 full32 约 7550–7635 万名/秒短测；三个独立方向的代表性结果是交换约 8093 万、紧凑字节扫描约 8454 万、含交换的分段 KSA 约 9626 万。分段独立跑 60.007 秒实际 **88,917,107 名/秒（53.78 T/周）**；叠加扫描与技能取模、放大批次后再做正式复测。计数归约与某个稀疏评分候选未采用；后者没过整字段对拍。

## WGSL：通用模板键环和降低回读往返

1. [宿主特化](../src/mining_gpu.rs) 只对实际 key 映射为 **单槽、Base16384、packed、名字 ≤64 B** 的模板生成 [常量键环](../generated-cycle.wgsl)，按用户模板实际字节展开，不写死测试名字或 ID。字面前后缀可变，尾段可落在任意相位，影子仍追加原来的 7 字节。长模板、多槽、Base64、wide 和上传走原通用路径。
2. [WGSL](../mining.wgsl) 由宿主一次打包初始 S-box 状态，恢复时批量读四个打包字；技能取模合并与 CUDA 等价。评分和命中筛选不变。
3. 每批把头部和前 4 条记录一起回读，超过 4 条走完整回读。属性过滤一旦通过必定完成评分，为相同的两个指标保留一个计数，避免重复原子操作；影子计数仍独立。
4. 影子只取前 31 项属性；大批次支持两行派发，并计算全局 ID。二维块大小 3,145,728 是本次实测较优点，不是所有设备的默认值。
5. 短筛去掉不够好的方案：私有 S-box、私有属性数组位打包、工作组原子归约、单模型先求分都没有胜出。预打包加通用键环第一次正式实测 82,587,322 名/秒，离目标约 0.10%，未向上取整算过线。

## 复现

从仓库根目录运行，新的输出目录不能已存在：

~~~powershell
$env:WGPU_BACKEND = 'vulkan'
pwsh -File wgpu-mine/benchmarks/build-cuda-ab.ps1
./target/release/examples/cuda-ab.exe --only wgsl --wgsl-block 32 --batch-size 3145728 --seconds 60 --rounds 1 --out target/cuda-ab/sprint-wgsl-repeat
./target/release/examples/cuda-ab.exe --only cuda --cuda-mode full --cuda-block 32 --batch-size 2097120 --seconds 60 --rounds 1 --out target/cuda-ab/sprint-cuda-repeat
~~~

这个长跑显式选择大批次：WGSL 按 3,145,728 个 176B 槽预分配两个缓冲，分别约 528 MiB；CUDA 按 2,097,120 个槽分配各约 352 MiB 的设备和页锁定宿主缓冲。另一个后端只参与验证时使用小容量。设备不支持该绑定大小或内存紧张时，使用 524287 或更小批次；正常 CLI 和基准原有批次默认值不变。旧二进制没有被本轮构建覆盖。只计一个后端可加 --only wgsl 或 --only cuda；仍先跑两后端的 CPU 完整对拍。正式 WGSL CLI 的 generated 模式也支持显式设定该上限；CPU、上传模式和旧 CPU/GPU 同量比较的限制不变。

## 验证

- [WGSL 硬件与 CLI 回归](../src/mining_gpu.rs)：库 37 项、CLI 单元 6 项、CLI 集成 6 项，启用硬件测试后 **49/49**。覆盖 wide/packed、上传和生成、工作组 32/64/128、Base64、重复占位符和 u64 边界。键序列另离线比较全部 1,128 种允许的前后缀字节长度组合（主/影子和两轮共 4,512 个序列）。
- 下游 Rust 宿主单独与 CPU 完整核对后缀、重复占位符与长模板，从 CPU/WGSL/CUDA 三边比较八围、技能、shadow 整数分子和 XP/XD 误差；默认用例含 65,537 个完整捕获、两处 257 项边界、32,771 个筛选候选。二行派发专项用首个已知命中作为第二行第一项，另带一个尾批，并核对同量 CUDA 阶段计数和完整 CSV；命中 ID 21,040,954 两边一致。
- 最终 WGSL 与重建 CUDA 的 **5,039,456,256** 个公共候选内 **184 条**完整命中逐行相同；与上轮 WGSL 的更短公共区间 145 条也逐行相同。
