## 使用

以下命令均在仓库根执行；构建统一使用 `-j2`，清除 `RUSTC_WRAPPER`，避免本机高并发内存/页面文件耗尽。

~~~powershell
$env:RUSTC_WRAPPER = ""
cargo build -p tswn --bins --release -j2

# 用户原参数保持可用；加有限右边界即可完整运行并安全结束。
target/release/tswn.exe -t2 -p550 -x4000 -d5000 --team shenjack -r10 -m "我也不知道我要测多少 []" --start 0 --end 1000000

# -t1 也走同一套 worker，没有专用单线程分支。
target/release/tswn.exe -t1 -p550 -x4000 -d5000 --team shenjack -b10000 --end 1000000

# 完整基准：仍计算生成、属性、必要技能/模型和命中 CSV 序列化，仅将输出换成 sink。
target/release/tswn.exe --bench -t6 -p550 -x4000 -d5000 --team shenjack -b10000 -m "我也不知道我要测多少 []" --end 5000000

# 正常写盘的可复现三次测量，逐样本保存，已有统计文件不会覆盖。
& miner/benchmarks/measure-cpu.ps1 -Candidates 5000000 -Threads 6 -Repetitions 3 -Output miner/benchmarks/cpu-local.csv
~~~

普通运行会在结果目录自动创建带纳秒时间戳的 CSV；同名文件使用 `create_new` 防止覆盖。队伍名中的文件名非法字符被替换，但 CSV 字段保留原始队伍名。参数错误退出码为 2，运行/I/O 错误为 1，正常结束为 0，协作中断为 130。

## 精确语义与调度

实现见 [cacluate.rs](../src/cacluate.rs)、[main.rs](../src/main.rs)。

- 范围严格为 `[start, end)`，不再为线程整除而改写右边界。允许空范围与 `end=u64::MAX`；后者不包含 `u64::MAX` 本身。
- 主线程独占范围游标，先求剩余量再钳制 batch，预热、固定尾块与动态尾块均不溢出。
- 每个 worker 有私有任务通道，消除共享接收器按错误 thread_id 丢任务的问题；移除共享可变引用的 transmute 和数据竞争。
- 主线程阻塞接收进度/命中，不忙等；正常结束、写错和中断均回收全部 worker。
- `-r` 优先于 `-b`。动态 batch 以速度乘秒数估计，再按剩余量/线程数钳制，避免首个预热完成的 worker 独占全部尾段；固定 batch 不额外改写。
- 可选亲和性保持 `if let Some` 语义，不指定就由操作系统调度，不默认绑相邻 SMT。
- 属性严格 `>p`，使用 HP+其余七围三倍和比较；XD/XP 分别按 Rust 饱和截断 `as u32 >= d/x`，三条件为 AND。
- 删除硬编码 24/165/250/380 有损门控。已知 raw 智力 16、实际八围 577 的候选不再被错误丢弃。

输出只有一个 BufWriter，用 `write_all` 处理短写，按 batch flush，结束时 flush+sync_all。表头始终存在，零命中/空范围也生成有效文件。CSV 固定 55 列：完整名字、ID、XP、XD、名字、队伍、8 属性、八围总值、按技能 ID 0..39 排列的 40 个频率；逗号、引号、CR/LF 正确转义。**这是对旧可变长、无表头输出格式的显式修正**；下游应按新表头读列。多线程行顺序不保证按 ID 升序。

## 保留的热点优化

实现见 [generate.rs](../src/generate.rs)、[name.rs](../src/name.rs)、[eval.rs](../src/evaluate/xuping/eval.rs)。

1. 模板每 worker 拆分一次，复用四个名字 String。Base16384、标准/URL Base64 在栈缓冲编码，十进制直接进位生成，保持大端字节与 padding，所有占位符都替换。
2. 队伍排列每 worker 只构造一次；第一轮 KSA 的固定模板前缀预处理一次，第二轮仍从 j=0 开始。四候选交错执行依赖链，不混合候选状态；尾部走真实单候选而非补齐重算。
3. 属性只解码前 31 个必需项；属性通过后才计算完整 128 项与技能。无损剪枝只依据用户阈值。
4. XP/QD 共享 f64 特征与按需影子属性，影子不做无用技能 PRGA；名字/队伍不再经 name@team 重新解析，原始字段里的 @ 与 NUL 也正确。
5. 不生成 1034 项模型临时数组，按线性项、上三角项顺序流式累加，只跳过精确为零的项。默认 SIMD 档保留旧 64 lane 的 f64 累加及 reduce_sum 顺序；标量后备也有完整模型路径。没有近似权重、FMA 改写或 PBB 有损门。
6. unsafe 仅用于有明确范围不变量的排列交换/已有 SIMD 技能读取；KSA 的运行时前缀检查在 release 也生效，ptr::swap 允许 i==j，未构造别名 &mut。技能写入使用检查索引，畸形排列不会因过滤项过多越界写。

新增验证包括：

- [reference.rs](../src/reference.rs) 独立安全 oracle 使用分配密钥、usize 取模、完整 PRGA 字节流和原逐索引多项式，不调用生产 KSA/属性/技能/展开算法，也不依赖 GPU crate。4608 个随机候选覆盖四种编码、UTF-8、多个占位符、@/NUL、技能与影子；另覆盖 255/256 字节、整个名字均为前缀、空名字与长队伍。
- 状态排列、8 属性、完整 128 项、40 个技能 ID、16 个有效频率逐项相等；模型与独立安全完整展开的误差 <1e-8，并验证 `as u32` 一致。
- 3000 个候选的流式模型与旧稠密 f64 路径误差 <1e-9；原多项式逐索引映射与新三角映射精确相同。
- 1/2/6 worker、固定/动态、空范围、预热短范围、非整除范围与 u64 上界每 ID 一次；短写、写失败、文件防覆盖、主动取消后 drain/join、动态尾块均分上限及参数错误。
- [validate-cpu.py](../benchmarks/validate-cpu.py) 24 组真实 CLI/CSV 验证：四编码×1/2/6线程×固定/动态，靠近 u64 上界，名字/队伍包含逗号、引号、换行；独立编码器逐项验证，Base16384 不使用有 U+8DFF 上界缺陷的源 decoder。
- 1000 个全命中 ID 的 55 列 CSV（含四位小数 XP/QD、属性、技能）与正确性基线逐字段完全一致。
- 实际 Windows 独立控制台 Ctrl-Break 已验收：收到中断后提前停止、join、落完整表头、退出 130。非零命中取消后保留完整行与无重复 ID 由单元测试覆盖。信号脚本仅控制自己启动的独立控制台，不触碰用户已有 miner。

## Ryzen 7 5800X 性能

构建为默认 release/SIMD，无额外 target-cpu 配置；固定 `-b10000`，模板为用户原模板，队伍 shenjack，属性阈值 550。每组重复三次，按基线→单路优化→四路优化交错、串行执行，不与 Lead 的构建/GPU/CPU 测量并行。

**环境背景负载：用户 PID 53344 的旧 -t2 无限 miner 自 01:27 持续运行，整个实验保留不动，约占两个 CPU 核心。以下是该背景下的相对结果，不是完全空闲整机峰值。**

基线是修复后的无损完整计算，不使用旧有损门控。普通写盘模式完成生成、必要完整技能/模型、命中格式化与写入，未为了测速跳过必要计算。

原始 36 样本见 [cpu-5800x-2026-10-30.csv](../benchmarks/cpu-5800x-2026-10-30.csv)，最终提交版本另有 [cpu-final-5800x-2026-10-30.csv](../benchmarks/cpu-final-5800x-2026-10-30.csv) 三次复核。单位均为候选/秒、中位数：

| 负载 | 候选/命中 | 正确性基线 | 单路优化 | 四路优化候选 | 最终提交复核 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 6线程，XP4000/XD5000 | 5,000,000 / 0 | 374,566 | 1,552,541 | 1,696,798 | **1,671,906** |
| 6线程，XP1500/XD3000 | 300,000 / 52,077 | 222,193 | 1,038,908 | 1,053,151 | — |
| 6线程，XP0/XD0 | 100,000 / 66,707 | 159,925 | 549,237 | 552,128 | — |
| 1线程，XP4000/XD5000 | 1,000,000 / 0 | 85,793 | 295,349 | 324,712 | — |

- 最终六线程原阈值相对修复基线 **4.46 倍**；包含进程启动、最终 sync_all 的墙钟中位从 374,081 提高到 **1,660,981 名/秒，4.44 倍**。
- 中命中/高命中候选分别约 **4.74/3.45 倍**；全程写入固定 55 列 CSV，而非仅内核或空 sink。
- 四路相对单路：六线程原阈值约 **+9.3%**，单 worker 约 **+9.9%**，因此保留。高命中受序列化/通道/磁盘影响，四路优势很小，不将这部分宣称为稳定的大幅收益。
- 最终原 `-t2 -r10` 参数加有限一百万范围：实算 1,000,000、零命中、1.592351 秒、628,002 名/秒，安全正常结束。
- `seconds` 是调度启动至计算、输出 flush、worker join 完成，末尾 sync_all 在此计时之外；`wall_seconds` 包含进程启动和末尾同步。短负载请优先看墙钟，勿把它与 GPU 内核单独计时比较。

## 已保留限制

- Windows Ctrl-C/Ctrl-Break 和正常有限范围可协作退出；强杀、断电、关闭控制台窗口的强制结束不提供断电事务保证。Unix 信号后备已实现，尚未在 Unix 实机验证。
- 中断后 CSV 保留已完成命中，但多 worker 的未完成区间没有自动 checkpoint/resume 文件；避免仅凭最大 ID 推断已完整覆盖前缀。
- 全量旧测试仍有上述三条历史模型期望不一致，下一步应以训练/模型来源核实旧断言，而不是改权重或期望凑绿。
- CPU 完整 f64 语义保留；没有为追求更多 SIMD 而近似模型。后续若继续优化高命中吞吐，优先测量 CSV 序列化与单 writer 的实际瓶颈。
