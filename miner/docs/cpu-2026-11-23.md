# CPU 矿工：等长 KSA 与稳定 SIMD 压缩

## 保留的改动

本轮以 `23139697fd03` 为基线，在 [10 月 CPU 复盘](cpu-2026-10-30.md) 已有的前缀与四路 KSA 上，保留两项独立优化：

1. [等长 KSA 分段](../src/name.rs#L53-L141)：同批候选字节长度相同时共享密钥游标，连续消费字节，只在段边界处理前导零。仍按 lane 独立交换，第二轮清零并从前导零起始；十进制跨位宽等混长批次走逐 lane 回绕。参考 [PBB 分段 KSA](../../../PBB/source/pbb/native/src/name.hpp#L268-L344)，保留 Rust 的前缀运行时检查，不要求 UTF-8 以 NUL 结尾。
2. [稳定 SIMD 压缩](../src/name.rs#L184-L204)：每 32 字节做仿射变换，环绕减 89 后比较是否小于 128，恰好选中原来的 [89,217)。按掩码从低位到高位写回 `value & 63`，属性解出前 31 项即停，技能阶段从原排列解出完整 128 项。参考 [PBB 掩码压缩](../../../PBB/source/pbb/native/src/utils.hpp#L495-L526)，使用可移植 SIMD，不新增 AVX2/BMI 指令集门槛，标量构建保留原过滤。

只参考了 PBB 源码；不运行 PBB，也不引入固定 V 早退、拟合门控或评分模型。XP/XD 权重与运算顺序、p/x/d 过滤条件、编号、调度和输出格式不变。

## 正确性

- [独立判定](../src/reference.rs#L162-L265) 验证整个排列、前 31 项和未写区、完整 128 项、PRGA、40 个技能 ID、频率、XP/XD 及整数截断；新增等长、混长、空名、前缀耗尽、UTF-8、内部 NUL 与十进制跨位宽分组对拍。
- 默认 SIMD 与 `--no-default-features` 各 29/29；按[旧报告](cpu-2026-10-30.md#L75-L81)过滤三个历史模型断言，未改模型和期望。
- KSA 单项、压缩单项、组合各过 24 组 CLI（四种编码、1/2/6 worker、固定/动态 batch、靠近 u64 上界、含逗号引号换行）；分别与新编译的 HEAD 对拍 1000 个全命中 ID 的全部 55 列。
- 真实写盘基准另比对 16 份输出：每份 86,921 个命中，ID 无重复，按 ID 排序后 55 列完全一致。统一摘要 `7745526b434890279eb261975e6becc966f3c1c7fbc2c8d123ef8da492282511`。

## 端到端配对基准

Windows x86-64、Ryzen 7 5800X、Rust nightly 1.102.0（3ef0c22cd）、默认 release/SIMD，无附加 CPU 架构参数。每种负载先预热，4 个串行交错块各测四版本，版本各占一次每个顺序位置；与正式 GPU 计时分开。固定 Base16384、队伍 shenjack、模板“我也不知道我要测多少 []”、批 10,000、从 0 开始。sink 模式仍保留完整评分和命中 CSV 序列化。

## 复现与剩余建议

以下命令在仓库根运行，脚本和产物都在隔离目录。先协调 CPU/GPU 时间窗。

~~~powershell
$root = 'target/cpu-opt-2026-11-23'
& "$root/build-variants.ps1"
& "$root/validate-variants.ps1"
$env:PYTHONIOENCODING = 'utf-8'
py -3 -B -u "$root/measure-paired.py" --output bench-paired-rerun.csv
py -3 -B -u "$root/verify-bench-csv.py" "$root/bench-paired-rerun.csv"
~~~

[构建脚本](../../target/cpu-opt-2026-11-23/build-variants.ps1) 在同一隔离源码位置换用四个版本，执行 `cargo +nightly build --release --offline --locked -p tswn --bin tswn -j2` 并复制各产物。首次从正式构建目录复制依赖文件到隔离 target，Cargo 命中 34 个已有构建单元；余下三个 release 变体只重编译 tswn。没有安装依赖；[正式 tswn.exe](../../target/release/tswn.exe) 的 SHA256 前后均为 `4EE17C35875E9FD8C01CD918F9D05A250E5307917F31DFD577A9625318045734`，正式产物未覆盖。

若要继续提速，先对当前组合做热点采样，确认高命中主要耗在 PRGA/虚评还是 CSV 序列化与单 writer，再试下一项；避免为这轮测试之外的 CPU 或编码推断收益。
